3｜Server／Client 系統架構

Dev63 架構原則
  • 前端隱藏 ≠ 授權：UI、路由守衛、PHP API、主機代理四層都要檢查角色。
  • Super 管理 API 維持「本機管理埠＋Super」；Admin 需要的功能另建狹義 API（只回傳摘要、只允許特定教材操作）。
  • Server App 與 Client App 都用 packages/ui；差異以 server 旗標與角色決定，不要複製一套畫面。
  • Page Atlas 私有索引只在 PHP 端（server/src/private/，不在 Nginx 的 server/public 根目錄下），前端 bundle 只有頁碼／頁名／路由。
Dev63 正式覆寫：Server App 僅 Super/Admin 可登入，User 後端拒絕；Client 登入後完全沒有 WOL；登入前公開 WOL 保留；PC 資訊 Super/Admin 可用。以下舊表格如有不同，以此為準。

層責任安全條件

Agent／DB掃描、教材 ID、metadata、衍生檔案工作沿用既有 scan；失敗可重跑且不重複建檔

匯入精靈七階段

  1. 偵測 USB：列出標籤、UUID、容量、格式、掛載狀態；處理 exFAT／NTFS／ext4 與無權限情況。
  2. 來源選擇：允許 USB 根目錄或子目錄、遞迴；只讀來源、排除 symlink 與特殊檔案。
  3. 目的選擇：只能 /Media 的允許子目錄；規範檔名、相對路徑、Unicode 與重名策略。
  4. 預覽：檔數、總容量、可用空間、重名與雜湊策略、預估作業量；不能把估計時間當保證。
  5. 確認：列出來源／目的／檔數與衝突處置；產生不可重複的 Job ID。
  6. 執行：.part 暫存、逐檔同步與 SHA-256 校驗、完成後原子改名；進度、失敗、取消、USB 中斷可重試。
  7. 建檔：只針對已完成檔案觸發既有深度掃描；輸出成功／略過／失敗明細與教材 ID。
